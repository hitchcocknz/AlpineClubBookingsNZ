## Summary

- **Parallel `verify`.** Typecheck, lint and the production build (with its nonce, prerender-manifest and server-only-boundary proofs, in their original order) are now the independent jobs `Typecheck`, `Lint` and `Production build`. They have no `needs:`, no job-level `if:` and no `continue-on-error`, and they run under `verify`'s exact environment. The required `verify` runs its cheap gates (PR-body gates, knip, render-mode and doc checks, file-size ratchet) and then makes one fail-closed poll through the existing `scripts/ci/require-test-shards.mjs`: `--job Typecheck --job Lint --job "Production build"` alongside the four unit shards. The new `--job` flag (`classifyRequiredJobs`) requires each named job exactly once. It fails at once on any completed conclusion other than success, a skip included, and treats a missing or running job as pending. It reuses the same poll loop, timeout, attempt-scoped `getAttemptJobs` read and name validation. Nothing was copied.
- **Path-aware migration jobs.** `Migration drift check` and `Data migration verification` keep their read-only coverage checks. A new unconditional step, `node scripts/ci/change-scope.mjs migrations`, decides whether the rest runs. Every later step skips only on an explicit `needed=false`. The `migrations` allowlist covers `prisma/`, `prisma.config.ts`, the toolchain manifests, every realdb test, helper and script those jobs' steps name, and the workflow and classifier.
- **Trivy image gate (owner decision, 26 Oct 2026).** The same kind of step (`change-scope.mjs image`) skips the build and scan on a pull request unless `package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml`, `patches/**`, `Dockerfile`, `docker-compose*.yml`, `.dockerignore` or the workflow changed. **One widening of the owner's list:** `.trivyignore` also triggers the scan, because it changes the gate's verdict. Every push, including every merge to `main`, scans in full. `ci.yml` has no `schedule` trigger and no other workflow runs Trivy, so in practice "the scheduled scan" is the push to `main`. The classifier also forces a full run for any non-PR event, so a schedule added later would scan too.
- **Shared classifier (INV-SSOT).** `scripts/ci/change-scope.mjs` now owns the PR change list (`pullRequestChangedFiles`), the fail-toward-running rule (`decideScope`: any non-PR event, listing error, thrown or garbled answer, or unknown scope means "needed") and the `GITHUB_OUTPUT` writer. `e2e-scope.mjs` keeps its own allowlist and now calls these instead of carrying its own copies.
- **Unit shards stay at 4** (measured; see Migration Or Deployment Impact).

## Migration Or Deployment Impact

- **No required-check name changes and no branch-protection change.** The three new jobs are not required contexts; they reach `verify` through its gate step.
- **Shard measurement** (12 recent green `ci.yml` runs, 25–26 Oct 2026, via the public API):
  - Per-shard job time: mean 4.9 min. The `pnpm test` step: median 4.0 min, max 5.3 min, plus ~0.7 min setup per shard.
  - Slowest shard per run: median 5.9 min, max 6.2 min.
  - `verify`: median 10.5 min (typecheck 3.25, build 2.6 + server-only proof 1.0, lint 2.5, in series). Run wall time: median 10.7 min.
  - Other jobs, median: `Static analysis gate` ~5.0 min (max 5.7), `Migration drift check` ~5.8, `Data migration verification` ~2.3, Trivy ~6.3.
- **Shard decision: stay at 4.** With `verify` split, the slowest shard (~5.9 min) is narrowly the critical path. Six shards would cut it to roughly 4 min, but `Static analysis gate` (~5.0, up to 5.7 min) would then set the pace, so the gain is at most ~0.2–0.9 min. The cost is two more runners per PR on top of the three this PR adds: CI would run 17 jobs and E2E 6, beyond the account's concurrent-job cap, which already queued shards for 25 min (run 40248216639, lesson 2 of #4405's handover). The issue's condition is necessary but not sufficient, so this is a deliberate call; a later PR can revisit it on measured post-split runs.
- **Expected wall time** for a typical PR (nothing under `prisma/`, no dependency or Docker change): the slowest of the slowest shard (~5.9), `Static analysis` (~5.0), `Production build` (~4.6), `Typecheck` (~4.2), `Lint` (~3.3), and the now near-instant migration and Trivy jobs. That is **≈6–6.5 min against the ~10.7 min baseline, saving ≈4–4.5 min**, in line with the issue's 5–6 min target. Runner time also falls by ~14 min per such PR (Trivy ~6.3 + drift ~5.8 + data migration ~2.3, less the scope steps). The three new jobs add ~2.5 min of setup between them.
- A PR that does touch `prisma/` or dependencies runs everything as before, in parallel, so it also gains the `verify` split.
